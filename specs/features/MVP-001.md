# MVP-001 — Sistema Signature en Stellar Testnet

## Objetivo

Entregar una demo funcional de creación, corrección, revisión, firma, custodia y verificación de contratos con historial inmutable y anclaje SHA-256 asíncrono en Stellar Testnet.

## Límites

- Mantener el frontend React/Vite existente y su estructura visual.
- Mantener un único backend modular en ASP.NET Core y PostgreSQL.
- Guardar archivos privados en SeaweedFS S3 y no enviar contenido ni datos personales a Stellar.
- Trabajar únicamente en feat/stellar-hackathon-mvp; no cambiar main ni producción.
- No incluir credenciales reales en código, configuración versionada, logs o informes.

## Criterios de aceptación

1. Compose incluye frontend, backend, PostgreSQL persistente y SeaweedFS persistente con archivos privados.
2. El esquema PostgreSQL se crea y evoluciona con migraciones; audit trail y Outbox quedan persistidos.
3. Los módulos de contratos, documentos, firmas y dashboard tienen API REST autenticada y OpenAPI.
4. Cada documento definitivo se guarda como objeto inmutable, tiene hash SHA-256, firmante, versión e histórico.
5. El anclaje Stellar Testnet se ejecuta fuera de la petición HTTP, con reintento e idempotencia; conserva estado y transaction hash.
6. La verificación compara el hash esperado con el objeto almacenado y consulta el dato de cuenta en Stellar.
7. La descarga requiere autorización y genera una URL prefirmada con vencimiento breve.
8. La interfaz existente consume métricas reales y permite crear, corregir, revisar, firmar, verificar y descargar.
9. El workflow de carga reproduce 100 usuarios concurrentes y registra throughput, p95, errores y resultado observado del gateway.
10. La guía de demo y los informes por fase distinguen resultados medidos, requisitos pendientes y bloqueos.

## Invariantes

- Los documentos definitivos y las filas de auditoría/firma son append-only.
- Las correcciones crean una versión nueva; nunca editan una versión firmada.
- La eliminación de contratos es lógica; no se elimina ningún objeto S3 desde la API.
- Solo se publica en Stellar el hash del documento definitivo y una clave derivada del hash.
- El anclaje en Stellar no incluye nombres, correos, referencias de negocio, contenido ni URL de documentos.
- La API de creación no espera a Stellar; una falla externa permanece visible y reintentable.
- Ninguna fase se califica como completada sin una comprobación y evidencia guardada.
